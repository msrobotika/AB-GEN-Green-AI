# AB-GEN leakage audit template

Use this checklist for every candidate golden baseline before promoting a result to `Reproduced`.

Allowed status values:
- `PASS` — evidence demonstrates the check is satisfied.
- `FAIL` — evidence demonstrates leakage or an invalid evaluation path.
- `UNKNOWN` — evidence is incomplete or ambiguous.

Any material `FAIL` or unresolved material `UNKNOWN` blocks `Reproduced` status.

## N2 stacking evidence requirements

N2 is a high-risk leakage boundary. Record explicitly:

- N1 fold construction;
- number of folds / holdout split;
- random seed(s);
- whether every N2 training row was generated by an N1 model that did **not** train on that row;
- how final N1 models were refitted after OOF feature generation;
- which data was used to fit polynomial/scaler transforms;
- which data was used to fit the final Ridge/MLP/other N2 estimator;
- whether the final test set was ever used during these choices.

If the historical implementation generated N2 training features from in-sample N1 predictions, mark `N2-1 = FAIL` even if the final accuracy can be reproduced.

## Rules

1. Do not replace `UNKNOWN` with `PASS` based on plausibility.
2. Do not retrain against final-test feedback to force a historical metric match.
3. Preserve failed candidate reconstructions and their logs.
4. Link supporting files by immutable hash/commit where possible.
5. A clean leakage audit validates the evaluation path; it does not by itself prove exact historical prediction reproduction.
